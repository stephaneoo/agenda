# Agenda v1 Implementation Plan

> **For agentic workers:** implement this plan task by task, in order, ticking the checkboxes as you go. Stop and report if a step's expected output doesn't match, or if a step would break a Global Constraint.

**Goal:** Ship the v1 slice of the spec: DATAtourisme ingestion into claims, the precomputed projection, the filtered list, occurrence pages with JSON-LD, the read API v1, offline reading and the moderation admin, running on a NixOS VM at Scaleway with tested backups and a one-command deploy.

**Architecture:** One Django project (apps `geo`, `claims`, `agenda`, `ingest`, `api`, `web`), packaged with uv2nix in a single flake that also defines the NixOS host, the deploy, the restore and the travel-matrix commands. Scaleway resources are declared with OpenTofu in `infra/`. Reads only touch canonical tables written by the projection.

**Tech stack:** Python 3.12, Django 5.x + GeoDjango, django-ninja, pytest-django, PostgreSQL 16 + PostGIS, uv2nix, NixOS, disko, nixos-anywhere, deploy-rs, Caddy, gunicorn, pgBackRest, OpenTofu + Scaleway provider, OSRM, vanilla JS (service worker, IndexedDB), `node --test` for JS unit tests.

**Spec:** `docs/specs/2026-10-25-agenda-v1.md`. The plan argues from the spec; read both.

**Decisions:** `docs/decisions/0001-nixos-with-pure-nix-packaging.md`, `0002-django-monolith.md`, `0003-licences.md`, `0004-event-first-model.md`, `0005-claims-with-precomputed-projection.md`

## Global Constraints

From the spec:
- Single VM, Scaleway.
- NixOS, with every service as a Nix module or package, and no docker.
- ZFS for data, unencrypted. PostgreSQL with PostGIS.
- Caddy as the web server.
- Django monolith: Django admin, django-ninja for the API, management commands on systemd timers.
- Zero-downtime migrations. Every breaking schema change is split over two deploys (expand, then contract), enforced by a check.
- Deploys go from the colleague's laptop, with git and one command. All checks run first, and the deploy is refused if any fails. No CI.
- The event is the primary record. Each occurrence has a stable URL.
- Per-source claims. Reads only touch the precomputed canonical tables, which only the projection code writes.
- AGPL code, Licence Ouverte data, reserved branding. DATAtourisme attribution includes the source and its last update date.
- Backups go offsite, to another region, and are tested by restoring them.
- Imported events are post-moderated: they are published automatically.

From 0001:
- No docker or compose on the host. Every service is a NixOS module or a Nix-built package.
- Deploys go through one command, which runs all checks first.
- Confirmation: the deploy command refuses to deploy when checks fail, and rolls back automatically when the post-deploy health check fails.

From 0002:
- Every breaking schema change is split over two deploys: expand, then contract.
- The public API is documented by a generated OpenAPI spec committed to the repo.
- The MCP server, when it comes in v2, calls the same service layer as the API. It has no separate data access.
- Confirmation: a check fails on a backward-incompatible migration not marked as a contract step; a check fails when the generated OpenAPI spec differs from the committed one.

From 0003:
- Never ingest an ODbL source without revisiting this decision.
- Images keep their own copyright and are not covered by the data licence.
- Confirmation: every page, feed and API response that carries DATAtourisme data cites the source and its last update date.

From 0004:
- Every occurrence has its own stable public URL, and that URL survives re-imports.
- Occurrence-level overrides (status, time) exist from v1.
- Confirmation: re-importing an unchanged source record leaves every occurrence ID and URL unchanged; cancelling one occurrence leaves the others untouched.

From 0005:
- Canonical tables are written only by the projection code, never directly.
- The projection is a pure function of the claims. A full rebuild command exists.
- Reads never compute the projection on the fly.
- Confirmation: a full rebuild equals the incremental projection; a moderator's hide survives the sync of a changed source record, while the other fields update.

Outward-facing actions (`tofu apply`, the first install with nixos-anywhere, the first deploy, pushing tags) are done only after the user confirms each one in the session.

## Review Focus

1. **DST transitions.** Today, 2026-10-25, is a DST change day. A local time of 02:30 on that day exists twice, and on the last Sunday of March it doesn't exist at all. Expected: on the October day, the first instance (+02:00) is taken. In March, the time moves forward to 03:00 +02:00. Tests go in Task 6 (`test_dst_ambiguous_and_nonexistent`).
2. **Network failure mid-pagination.** Expected: the run is marked failed, no withdrawals happen, any updates already applied stay, and `last_success` doesn't advance. Test goes in Task 10 (`test_fetch_error_mid_pagination_withdraws_nothing`).
3. **Rows with bad or missing coordinates.** Includes the Enclave des Papes, a part of Vaucluse surrounded by Drôme, and points in a neighbouring commune just outside the area. Expected: point-in-polygon decides; with no coordinates, it falls back to postcode plus commune name; when nothing resolves, the row is skipped and counted, not guessed. Test goes in Task 10 (`test_commune_resolution_edge_cases`).
4. **Cursor stability while the projection changes between two pages.** Expected: a keyset cursor on `(start, id)` gives no duplicates and skips no rows that were unchanged. Test goes in Task 7 (`test_cursor_stable_under_concurrent_projection`).
5. **Date-range overlap for spanning and date-only occurrences.** Example: an exhibition from 2026-10-01 to 2026-12-31 queried for `from=to=2026-11-05`; a date-only `end` counts as inclusive to 24:00. Expected: the occurrence matches. Test goes in Task 7 (`test_overlap_spanning_and_date_only`).

  - `agenda.categories.SLUGS`: the 11 slugs from the spec, with French labels.
